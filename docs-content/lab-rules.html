กฎ 2 ชุดที่ใช้คู่ขนาน

ต้นฉบับ Blueprint บอกว่ามี “กฎ 10 ประการ” แต่ไม่ได้ระบุรายการ ฉบับร่างสองฉบับจึงแต่งขึ้นมาคนละชุด เมื่ออ่านละเอียดพบว่าไม่ได้ขัดกัน แต่อยู่คนละชั้น: ชุด R กำกับ ทั้งระบบ ส่วนชุด C กำกับ การประชุมของสภา Creative Friction จึงใช้คู่ขนานกันได้

ร่างแรก · รอคุณรับรอง ทั้งสองชุดเรียบเรียงจากเนื้อหาต้นฉบับ พร้อมใช้เป็นร่างแรก ปรับถ้อยคำได้ตามระบบของคุณ แล้วรับรองเป็นกฎบัตรทางการ

ชุด R — กฎบัตรระบบ (ใช้ทุกคำขอ)

#กฎสาระ
R1Least-Capability Leasingไม่ถือเครื่องมือถาวร ได้สิทธิ์ชั่วคราวเฉพาะภารกิจย่อย
R2Exclusive State Ownershipเจ้าของสถานะรายเดียว RunState เป็น checkpoint ไม่ใช่ที่เก็บที่สอง
R3Explicit Approval Pathside-effect ทุกชนิดผ่าน Approval Gate ที่ระบุชื่อ
R4No Production Self-Modificationแก้พรอมต์/ทักษะ/นโยบายผ่าน Shadow Reflection + Promotion Gate เท่านั้น
R5Evidence-Bound Claimsข้ออ้างต้องชี้ Source ID, Tool Call ID, Artifact Path, Trace Span ID ได้
R6Zero-Trust Inputsinput และ output ของเครื่องมือต้องผ่าน structured extraction + schema validation
R7Fail-Closed Defaultนโยบายหรือการตรวจล้มเหลว → หยุดทันที
R8Eval-Gated Promotionทุก change proposal ผ่าน offline eval + regression gate และมี rollback point
R9Action-Ladder RoutingOBSERVE/DRAFT → read-only lane; PREPARE/EXECUTE → ผ่าน Approval Gate ก่อน
R10Budget-Aware Frictionเรียกสภาเฉพาะความเสี่ยงสูง (HIGH หรือ PREPARE/EXECUTE) ที่เหลือใช้ fast lane

ชุด C — กฎการประชุมของสภา (ใช้เมื่อ R10 เรียกสภา)

#กฎสอดคล้องกับ
C1ทุกแผนต้องผ่านการทดสอบสมมติฐานR5
C2Breaker มีสิทธิ์ยับยั้งแบบส่งกลับ (suspensive veto)R7
C3Evidence Skeptic กำหนดภาระการพิสูจน์R5
C4Constraint Broker คุมงบประมาณเวลาและต้นทุนR10
C5Convergence Judge ตัดสินขั้นสุดท้ายR3
C6ห้าม groupthink: ทุกบทบาทต้องให้ความเห็นแยกกันก่อนรวม—
C7ห้าม confirmation bias: หลักฐานแย้งต้องถูกบันทึกใน Proposal PackR5
C8Proposal Pack มีทางเลือกอย่างน้อย 2 แนวทาง—
C9ห้ามกลับไปใช้สมมติฐานที่ถูกตีตกโดยไม่มีหลักฐานใหม่R5
C10แผนที่ผ่านต้องมีแผนสำรองหรือ rollbackR8

จุดที่ดูเหมือนขัด และข้อยุติ

ดูเหมือนขัดข้อยุติที่ทำให้ใช้คู่กันได้
C1 “ทุกแผนต้องทดสอบ” vs R10 “เรียกสภาเฉพาะงานเสี่ยงสูง”กฎ C ใช้เฉพาะเมื่อสภาถูกเรียก งานใน fast lane ไม่ต้องผ่านสภา แต่ยังอยู่ใต้กฎ R ครบทุกข้อ
C2 “Breaker ยับยั้งได้” vs C5 “Judge ตัดสินขั้นสุดท้าย”veto ของ Breaker เป็นแบบส่งกลับ: แผนต้องกลับไปแก้หรือบันทึกเหตุผลที่ไม่รับข้อคัดค้าน Judge จึงตัดสินได้ ห้ามตัดสินทับข้อคัดค้านที่ยังไม่ถูกตอบ
C8 “ต้องมี 2 ทางเลือก” vs R10 “คุม latency”ทางเลือกที่สองอาจเป็นแค่ “ไม่ทำ / ทำแบบ dry-run” ไม่ต้องวางแผนเต็มสองชุด
