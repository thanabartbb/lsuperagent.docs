กฎของระบบ

กฎแบ่งเป็น 2 ชุด ชุด R ใช้กับทุกคำขอ ส่วนชุด C ใช้ตอนที่สภา Creative Friction ประชุมพิจารณาแผน

ชุด R: กฎของระบบ

#กฎสาระ
R1Least-Privilege Tool Accessไม่ถือเครื่องมือถาวร ได้สิทธิ์เฉพาะงานย่อยที่ทำอยู่
R2Exclusive State Ownershipเจ้าของสถานะรายเดียว RunState เป็นจุดพักของรันเดิม ไม่ใช่ที่เก็บประวัติชุดที่สอง
R3Explicit Approval Pathการเปลี่ยนแปลงระบบทุกชนิดผ่าน approval gate ที่ระบุชื่อ
R4No Production Self-Modificationแก้พรอมต์ ทักษะ หรือนโยบายผ่าน Shadow Reflection และ Promotion Gate เท่านั้น
R5Evidence-Bound Claimsข้ออ้างต้องชี้ Source ID, Tool Call ID, Artifact Path และ Trace Span ID ได้
R6Zero-Trust Inputsinput และ output ของเครื่องมือผ่าน structured extraction และ schema validation
R7Fail-Closed Defaultนโยบายหรือการตรวจล้มเหลว ระบบหยุดทันที
R8Eval-Gated Promotionทุกการเปลี่ยนแปลงผ่าน offline eval และ regression gate และมี rollback point
R9Action-Ladder RoutingOBSERVE/DRAFT ไป read-only lane ส่วน PREPARE/EXECUTE ต้องผ่าน approval gate
R10Budget-Aware Frictionประชุมสภาเฉพาะงานความเสี่ยงสูง งานอื่นใช้ fast lane

ชุด C: กฎการประชุมของสภา

#กฎสัมพันธ์กับ
C1ทุกแผนต้องผ่านการทดสอบสมมติฐานR5
C2Breaker ยับยั้งได้โดยส่งแผนกลับไปแก้R7
C3Evidence Skeptic กำหนดภาระการพิสูจน์R5
C4Constraint Broker คุมเวลาและต้นทุนR10
C5Convergence Judge ตัดสินหลังตอบข้อคัดค้านครบR3
C6ทุกบทบาทเสนอความเห็นแยกกันก่อนรวม—
C7หลักฐานแย้งต้องบันทึกใน Proposal PackR5
C8Proposal Pack มีทางเลือกอย่างน้อย 2 แนวทาง (อาจเป็น “ไม่ทำ” หรือ dry-run)—
C9ไม่กลับไปใช้สมมติฐานที่ตกไปแล้วโดยไม่มีหลักฐานใหม่R5
C10แผนที่ผ่านต้องมีแผนสำรองหรือ rollbackR8
