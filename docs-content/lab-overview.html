AGENTS-SDK-LAB

สถาปัตยกรรมอ้างอิง (reference architecture) สำหรับระบบ multi-agent ที่อิงหลักฐานและเช่าสิทธิ์เครื่องมือแบบชั่วคราว สร้างบน OpenAI Agents SDK (Python) + Responses API + MCP หมวดนี้รวมสองฉบับร่างเข้าด้วยกัน แก้จุดที่ขัดกันด้วยการตรวจกับโค้ดจริง และแตกเป็นหน้าเล็ก ๆ ให้เรียนทีละเรื่อง

สถานะ: สถาปัตยกรรมอ้างอิงและโค้ดเพื่อการเรียนรู้ ไม่ใช่ระบบ production สำเร็จรูป เครื่องมือในตัวอย่างเป็น [SIMULATED] คืนข้อความตายตัวและไม่เปลี่ยนระบบจริง

ปัญหาที่ต้องการแก้

ปัญหาคำอธิบายผลกระทบ
Context Explosionใส่สคีมาเครื่องมือจำนวนมากลงพรอมต์ทุกรอบต้นทุนโทเคนสูง โมเดลเลือกเครื่องมือผิด
Side-effect Indeterminismผลกระทบต่อระบบภายนอกคาดเดาและควบคุมไม่ได้ความเสี่ยงด้านความปลอดภัย สถานะเปลี่ยนโดยไม่ตั้งใจ
Traceability Deficitสืบย้อนไม่ได้ว่าข้อสรุปมาจากหลักฐานใดตรวจความถูกต้องไม่ได้ ขาดความน่าเชื่อถือ

ปรัชญา 4 มิติ

  1. Capability-minimal — ให้สิทธิ์เครื่องมือเท่าที่ภารกิจย่อยต้องใช้
  2. Evidence-carrying — ผลลัพธ์ผูกกับหลักฐานที่ตรวจย้อนได้
  3. Approval-aware — การกระทำที่มีผลข้างเคียงต้องผ่านเส้นทางอนุมัติ
  4. Eval-driven — ปรับปรุงระบบผ่านการประเมินเชิงปริมาณ ไม่ใช่ความรู้สึก

ต่างจาก Global God-Agent อย่างไร

เฟรมเวิร์กทั่วไปมักมีเอเจนต์ตัวเดียวถือเครื่องมือและสถานะทั้งหมดตลอดอายุการทำงาน AGENTS-SDK-LAB ปฏิเสธแบบนั้น: เครื่องมือถูก เช่า ตามระดับความเสี่ยงของแต่ละขั้น และสถานะมีเจ้าของรายเดียว

เส้นทางการเรียน

1. ข้อตกลงสถาปัตยกรรม →4 ข้อที่ห้ามประนีประนอม 2. 8 ระนาบ →ภาพรวมแล้วลงลึกทีละระนาบ 3. ลงมือทำ →ติดตั้งและรันแบบออฟไลน์ได้ทันที 4. ข้อขัดแย้งและข้อยุติ →จุดที่สองฉบับร่างไม่ตรงกัน และคำตอบที่ตรวจแล้ว
