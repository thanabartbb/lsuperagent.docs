Retry และ timeout

SDK ลองใหม่ให้อัตโนมัติเมื่อปัญหาน่าจะหายเอง

เมื่อไหร่ที่ retry

  • HTTP 408, 409, 429 และ 5xx
  • เครือข่ายล้มเหลวหรือ timeout

ไม่ retry เมื่อได้ 400, 401, 404 ฯลฯ เพราะส่งซ้ำก็ได้ผลเดิม

SDK retry ทุกเมธอดรวมถึง POST ถ้าคำขอ /chat หรือ /image ไปถึงเซิร์ฟเวอร์แล้วแต่คำตอบหายหรือหมดเวลา SDK จะส่งซ้ำ ทำให้สร้างผลลัพธ์ซ้ำ เสียโควตาเพิ่ม และอาจเสียค่าใช้จ่ายซ้ำ API ยังไม่มี idempotency key ถ้ารับผลซ้ำไม่ได้ให้ตั้ง maxRetries: 0 สำหรับคำขอสร้างเนื้อหา

await client.post('/image', { body: { prompt }, maxRetries: 0, timeout: 180_000 });

ระยะรอ

ถ้าเซิร์ฟเวอร์ส่ง Retry-After (0–60 วินาที) SDK จะรอตามนั้น ไม่งั้นใช้ exponential backoff: 0.5s, 1s, 2s … สูงสุด 8s พร้อม jitter

API ของเว็บนี้จำกัด 10 คำขอ / 10 นาที ต่อ IP และเครื่องมือ นับในหน่วยความจำของ Worker แต่ละ isolate (ไม่ใช่โควตาต่อ API key หรือโควตารวม คนที่ใช้ IP เดียวกันจะนับรวมกัน) เมื่อเกินจะได้ 429 พร้อม Retry-After ที่อาจยาวถึง 600 วินาที ซึ่งเกิน 60 วินาทีที่ SDK ยอมรอ SDK จึง retry เร็ว ๆ แล้วได้ 429 ซ้ำ ให้จับ APIError แล้วรอตาม header เอง

try {
  await client.post('/chat', { body: { message: 'hi' }, maxRetries: 0 });
} catch (err) {
  if (err instanceof APIError && err.status === 429) {
    const waitSeconds = Number(err.headers.get('retry-after') ?? 60);
    console.log(`รออีก ${waitSeconds} วินาทีก่อนส่งใหม่`);
  }
}

ปรับค่า

// ทั้ง client
const client = new Lsupergen({ baseURL: '{{BASE}}', maxRetries: 4, timeout: 30_000 });

// เฉพาะคำขอเดียว
await client.get('/health', { maxRetries: 0, timeout: 5_000 });

ยกเลิกคำขอ

const controller = new AbortController();
setTimeout(() => controller.abort(), 3_000);
await client.post('/chat', { body: { message: 'hi' }, signal: controller.signal });

ถ้ายกเลิกระหว่างที่คำขอกำลังส่ง SDK จะไม่ retry และโยน error ต้นทาง (AbortError) ออกมา

ข้อจำกัดของ 0.1.0: ถ้า signal ถูกยกเลิกไปแล้วก่อนเริ่ม หรือยกเลิกระหว่างที่ SDK กำลังรอเพื่อ retry คำขอถัดไปจะยังถูกส่งออกไป และอาจจบด้วย APIError แทน AbortError ถ้าต้องการให้การยกเลิกหยุดทุกอย่างจริง ให้ตั้ง maxRetries: 0 และเช็ก signal.aborted ก่อนเรียก
