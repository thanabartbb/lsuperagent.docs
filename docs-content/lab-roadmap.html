เส้นทางสู่ production

สิ่งที่เสร็จแล้วคือรากฐานที่ตรวจและทดสอบจริง หน้านี้แบ่งงานที่เหลือเป็นขั้นเล็ก ๆ ทำทีละขั้นได้ ทุกขั้นมีวิธีเช็กว่าเสร็จ

✅ เสร็จแล้ว

  • สถาปัตยกรรม 8 ระนาบ + ข้อตกลง 4 ข้อ + กฎร่างแรก 2 ชุด
  • Harness ที่ประกอบทุกระนาบเข้าด้วยกัน รันได้ทั้งออฟไลน์และกับ OpenAI จริง
  • อนุมัติ 2 ชั้น (แผน + เครื่องมือ) ใช้กลไกของ SDK จริง ทดสอบทั้งกรณีอนุมัติและปฏิเสธ
  • Evidence ledger, trace grader, dispatcher, compaction trigger — ชุดทดสอบ 10/10
  • ทุกข้ออ้างที่ขัดกันถูกตรวจกับแพ็กเกจจริงแล้ว

🔜 ขั้นต่อไป

  1. เสียบระบบจริงแทนเครื่องมือตัวอย่าง
    แก้ตัวฟังก์ชันใน lab_harness.py ให้เรียก API ของคุณ คง needs_approval=True ไว้กับเครื่องมือที่เปลี่ยนระบบ 
    import httpx

@function_tool
def read_system_status(service_name: str) -> str:
    """Read a service's status (OBSERVE)."""
    r = httpx.get(f"https://status.example.internal/api/{service_name}", timeout=10)
    r.raise_for_status()
    return r.text
    เสร็จเมื่อ: ledger แสดงผลจากระบบจริง และปฏิเสธที่ชั้นเครื่องมือแล้วระบบไม่ถูกแตะ
  2. รันกับ OpenAI จริง
    export OPENAI_API_KEY=... แล้ว python lab_harness.py
    เสร็จเมื่อ: ทั้งสองกรณีได้ trace_status: PASS กับโมเดลจริง
  3. เก็บสถานะถาวร
    ใช้ SQLiteSession("ชื่อไฟล์.db") ครอบด้วย OpenAIResponsesCompactionSession ตาม State 3 โหมด
    เสร็จเมื่อ: ปิดแล้วเปิดโปรแกรมใหม่ บทสนทนายังต่อได้
  4. ยกระดับ Trace Grader
    เพิ่มการตรวจว่าทุกข้ออ้างใน final_claim ชี้กลับไปยัง tool_end ใน ledger ได้ (Claim-Evidence Map)
    เสร็จเมื่อ: มี test ที่คำตอบแต่งข้อมูลเองแล้ว grader ได้ FAIL
  5. เพิ่ม test จากเหตุการณ์จริง
    ทุกครั้งที่เจอ trace ที่ผิด เขียนเป็น test ด้วย ScriptedModel (ระนาบ 7)
    เสร็จเมื่อ: ชุดทดสอบโตขึ้นตามปัญหาที่เจอ และรันทุกครั้งก่อนปล่อยเวอร์ชัน
  6. รับรองกฎบัตร
    ทบทวน กฎ R และ C ปรับถ้อยคำ แล้วเปลี่ยนป้ายเป็น “รับรองแล้ว”
  7. ต่อ CI
    ให้ GitHub Actions รัน pytest ใน assets/lab/ ทุก PR คู่กับ test ของเว็บที่มีอยู่แล้ว

ไม่ต้องทำครบทุกขั้นพร้อมกัน ขั้นที่ 1–2 อย่างเดียวก็ได้ระบบที่ทำงานกับข้อมูลจริงและมีระบบอนุมัติ 2 ชั้นแล้ว
