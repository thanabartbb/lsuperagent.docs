โครงสร้างระบบ (core)

“core” ของเว็บ agents-sdk.space คือ Cloudflare Worker ตัวเดียว ทุกคำขอผ่านมันก่อนเสมอ แล้วมันตัดสินใจว่าจะตอบ API เอง หรือส่งไฟล์ HTML ให้เบราว์เซอร์

เส้นทางของคำขอ

เบราว์เซอร์ / SDK
  ↓
Cloudflare Worker "lsuperagent-docs"      (wrangler.toml)
  ↓
src/firebase-worker.js                     ← จุดเข้า: login ด้วย Firebase / email
  ↓
src/index.js                               ← core: routing, session, API, AI
  ├─ /v1/*            → API ของ SDK (health, me, chat, image)
  ├─ /api/chat        → แชทในหน้าเว็บ (ใช้ session cookie)
  ├─ /docs/:page      → docs-shell.html (หน้าเอกสารนี้)
  ├─ /guide           → guide.html (Playground)
  └─ อื่น ๆ           → ไฟล์ static ใน repo (html, css, js)

ไฟล์สำคัญ

ไฟล์หน้าที่
wrangler.tomlตั้งค่า Worker: ชื่อ, จุดเข้า, โฟลเดอร์ static
src/index.jscore ทั้งหมด: เส้นทาง URL, ตรวจ login, เรียก OpenAI, API v1
src/firebase-worker.jslogin ผ่าน Firebase แล้วส่งต่อให้ index.js
docs-shell.html + assets/docs.*โครงหน้าเอกสาร (sidebar, ค้นหา, สารบัญ)
assets/docs-nav.jsรายการเมนูด้านซ้าย
docs-content/*.htmlเนื้อหาแต่ละหน้าเอกสาร
tests/*.test.mjsชุดทดสอบ รันด้วย node --test tests/*.test.mjs

การ deploy

merge เข้า branch main แล้ว Cloudflare Workers Builds จะ build และ deploy ให้อัตโนมัติ ความลับทั้งหมด (OPENAI_API_KEY, AUTH_SESSION_SECRET ฯลฯ) ตั้งใน Cloudflare dashboard ไม่อยู่ใน repo

ทำไมไม่ใช้ Docus/Nuxt

Docus สร้างด้วย Nuxt ต้องมีขั้น build และเปลี่ยนโครงสร้างทั้งเว็บ ระบบเอกสารนี้ทำหน้าที่เดียวกัน (sidebar แบ่งหมวด, ค้นหา, สารบัญ, ก่อนหน้า/ถัดไป) ด้วย HTML + JS ธรรมดาที่รันบน Worker เดิมได้เลย
