ข้อขัดแย้งและข้อยุติ

จุดที่ฉบับร่าง A (ไฟล์ .md ที่ดาวน์โหลดมา) และฉบับร่าง B (Kimi) ไม่ตรงกัน พร้อมคำตอบที่ได้จากการตรวจแพ็กเกจจริงและเอกสารทางการ

วิธีตรวจ

  • ติดตั้ง openai-agents==0.22.3 แล้วตรวจ class และ signature ด้วย inspect
  • อ่านซอร์สของ SDK ในจุดที่เอกสารอ้าง (เช่นข้อจำกัดของ PTC และ compaction)
  • รันโค้ดทั้งหมดกับ ScriptedModel ชุดทดสอบ 10 ข้อผ่านทั้งหมด
  • เทียบกับหน้า Tools ของเอกสาร OpenAI Agents SDK ทางการ

ตารางข้อยุติ

เรื่องฉบับ Aฉบับ Bข้อยุติ
กฎ 10 ข้อR1–R10 (กฎระบบ)อีกชุด (กฎการประชุมสภา)อยู่คนละชั้น ใช้คู่ขนาน → ชุด R และชุด C ร่างแรก · รอคุณรับรอง
SandboxAgent“ยังไม่พบในเอกสาร”ใส่ในตารางเหมือนยืนยันแล้วมีจริงที่ agents.sandbox.SandboxAgent แต่ไม่อยู่ใน agents ระดับบน ยืนยันแล้ว
การอนุมัติinput() ก่อนรัน“Approvals API”ใช้ทั้งสองชั้น: plan gate + needs_approval/RunState → Approval 2 ชั้น ยืนยันแล้ว
โมเดลgpt-5o3-miniไม่ hardcode ใช้ค่าเริ่มต้นของ SDK หรือกำหนดเอง ใน 0.22.3 ค่าเริ่มต้นคือ gpt-5.6-luna tool search/PTC ต้องเป็น Responses model ที่รองรับ ยืนยันแล้ว
“gpt-5.4 ขึ้นไป”ยืนยัน—เอกสารทางการเขียนแค่ “OpenAI Responses models” ตัวเลขนี้มาจาก LiteLLM ยังไม่ยืนยัน
PTC ต่อเอเจนต์ไม่ระบุสูงสุด 1ถูก: SDK โยน UserError ถ้ามีมากกว่า 1 ยืนยันแล้ว
MCPHostedMCPToolMCPServerStdioถูกทั้งคู่: โฮสต์ = HostedMCPTool, โลคัล = agents.mcp.MCPServerStdio ยืนยันแล้ว
Compactionเขียนเงื่อนไข 80% เองอ้าง /responses/compactใช้ OpenAIResponsesCompactionSession + ฟังก์ชัน 80% เป็น should_trigger_compaction ใช้ครอบ conversation session ไม่ได้ ยืนยันแล้ว
Hooksเขียนครบ# ... implementต้องเขียนครบ ไม่งั้น ledger ว่างและ grader FAIL ทุกครั้ง ใช้ของฉบับ A ที่ signature ตรงกับ 0.22.3 ยืนยันแล้ว
Dispatcher—อ้าง handler ที่ไม่มีประกาศครบและทดสอบแล้ว → Action Ladder ยืนยันแล้ว
สถานะเอกสารเอกสารอ้างอิง“Production Ready”สถาปัตยกรรมอ้างอิง + โค้ดเรียนรู้ เครื่องมือเป็น [SIMULATED]
openai>=2.25.0—อ้างเป็นเงื่อนไขไม่พบในซอร์ส ใช้เวอร์ชันที่ openai-agents ติดตั้งให้ (ตอนตรวจได้ openai 3.19.2) ยังไม่ยืนยัน
โดเมนagent-sdk.spaceที่ถูกคือ agents-sdk.space

ข้อค้นพบใหม่ที่ทั้งสองฉบับไม่ได้พูดถึง

  • Output guardrail กับสถานะฝั่งเซิร์ฟเวอร์ใช้ร่วมกันไม่ได้ — ระนาบ 6 (ตรวจหลักฐานด้วย output guardrail) ชนกับโหมด conversation_id/previous_response_id ของระนาบ 2 ข้อยุติ: ถ้าต้องตรวจ output ให้ใช้ SDK Session ยืนยันแล้ว
  • เรียกเครื่องมือที่ไม่ได้รับสิทธิ์ — SDK โยน ModelBehaviorError ซึ่งสอดคล้องกับ fail-closed (R7) ยืนยันแล้ว
